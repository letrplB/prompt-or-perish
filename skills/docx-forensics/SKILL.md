# DOCX Forensic Analysis — AI Generation Detection

Perform a systematic forensic inspection of a .docx file to determine whether it was genuinely authored by a human in Microsoft Word or generated by an AI system and programmatically assembled. Produce a structured evidence report.

## When to Use

Invoke when the user:
- Suspects a student report or submission was AI-generated
- Wants to verify the authenticity of a .docx document
- Asks to forensically analyze a Word document
- Says "check this document", "is this AI-generated", or "/docx-forensics"

## Inputs

**Required:**
- Path to a `.docx` file

**Optional:**
- `--output <path>` — destination for the markdown report. Default: `<docx_basename>.forensics.md` next to the input file.

## Phase 1: ZIP-Level Inspection

Extract and analyze the .docx as a ZIP archive using Python's `zipfile` module.

### 1a. File Inventory & Timestamps

```python
import zipfile
with zipfile.ZipFile(docx_path, 'r') as z:
    for info in z.infolist():
        # Record: filename, file_size, date_time
```

**Check for:**
- **Uniform 1980-01-01 00:00:00 timestamps** — the default epoch for Python's `zipfile` module. This is a near-definitive indicator of programmatic .docx assembly (python-docx, docx libraries). Real Word documents carry actual save timestamps.
- **All identical timestamps** — even if not 1980, uniform timestamps across all files suggest single-pass generation rather than incremental editing.
- **Missing expected files** — e.g., no `comments.xml`, no `footnotes.xml` in a long document suggests minimal Word feature usage.

**Evidence strength if positive: DEFINITIVE**

### 1b. Core Metadata (docProps/core.xml)

Extract and record:
- `dc:creator` — often a person's name; suspicious if it's a project label, generic text, or LLM-generated name
- `cp:lastModifiedBy` — check if this matches anyone in the expected group
- `dcterms:created` / `dcterms:modified` — creation and modification timestamps
- `cp:revision` — number of saves

**Red flags:**
- Creator is not a person's name (e.g., "Seminar Report SS1", "Assignment", "Document")
- `lastModifiedBy` is an unknown person — could indicate third-party involvement
- Very few revisions for a long document
- Creation timestamp at unusual hours (e.g., 2:16 AM for a student report)

### 1c. App Metadata (docProps/app.xml)

Extract and record:
- `TotalTime` — claimed editing time in minutes
- `Pages`, `Words`, `Characters`
- `Application` and `AppVersion`

**Red flags:**
- Implausible TotalTime relative to document length and revision count
- Very high word count with very few revisions

### 1d. Bibliography Sources (customXml/item1.xml)

Check for:
```xml
<b:Sources ... SelectedStyle="..." StyleName="..." Version="..."></b:Sources>
```

**Red flags:**
- Empty `<b:Sources>` with references in the document text — confirms no citation management tool was used
- References formatted as plain text rather than Word field codes

**Evidence strength if positive: STRONG**

## Phase 2: Document XML Deep Analysis

Parse `word/document.xml` using `xml.etree.ElementTree`.

### 2a. Revision Save ID (rsid) Analysis

Every paragraph in Word carries rsid attributes that fingerprint which editing session created or modified it.

```python
from collections import Counter
# For each <w:p>: extract w:rsidR, w:rsidRDefault, w:rsidRPr
```

**Check for:**
- **Dominant single rsidR** — if >70% of paragraphs share the same rsidR, the document was created in a single pass (programmatic or paste-all-at-once)
- **rsidRDefault = 00000000** — the null ID, characteristic of programmatically inserted content never touched in Word's editor
- **Total unique rsid count** — a genuinely written 10+ page document should have dozens to hundreds of unique rsids. Fewer than 15 is suspicious.

**Benchmarks:**
- Human-written 10-page doc: 50-200+ unique rsids
- AI-generated + programmatic assembly: 5-15 unique rsids
- AI-generated, pasted into Word, minor edits: 15-30 unique rsids

**Evidence strength if positive: DEFINITIVE**

### 2b. Chemical Formula & Scientific Notation Rendering

Count two rendering methods across all text runs:

1. **Word-native formatting**: `<w:vertAlign w:val="subscript"/>` or `<w:vertAlign w:val="superscript"/>` in run properties
2. **Unicode characters**: subscripts (U+2080–U+2089: ₀₁₂₃₄₅₆₇₈₉) and superscripts (U+2070–U+2079, U+207A–U+207E: ⁰¹²³⁴⁵⁶⁷⁸⁹⁺⁻)

**Interpretation:**
- **100% Unicode, 0% Word-native** — near-certain LLM generation. Students writing in Word use Ctrl+= / Ctrl+Shift+= for sub/superscripts.
- **Mixed** — possible human editing of AI-generated text, or copy-paste from web sources
- **100% Word-native** — consistent with human authoring in Word

**Note:** This check is most valuable for STEM documents with chemical formulas, mathematical notation, or unit expressions (e.g., mAh g⁻¹). Skip for humanities documents.

**Evidence strength if positive: VERY STRONG (for STEM docs)**

### 2c. Prompt / Instruction Artifact Scan

Search all paragraph text for patterns that indicate leftover AI prompts or generation instructions:

**Patterns to match (case-insensitive):**
- `[FIGURE` or `[TABLE` followed by instruction text (e.g., "[FIGURE 3 — Insert SEM images...]")
- `Mark `, `Highlight `, `Indicate ` at the start of a paragraph (figure annotation instructions)
- `[to be added]`, `[insert`, `[placeholder`
- `[Institute Name]`, `[University]`, `[Supervisor]`, `[Author]`, `[Your Name]`
- `TODO`, `NOTE:`, `FIXME` in body text (not code blocks)
- Paragraphs that read as instructions rather than content (imperative mood directing figure/table creation)

**Evidence strength if positive: VERY STRONG**

### 2d. Section & Layout Properties

Check `<w:sectPr>` elements for:
- Column count — is a two-column journal layout used for a student report?
- Page size and margins
- Whether the layout mimics a specific journal template

**Red flags:**
- Journal-paper formatting for a seminar report / homework / thesis chapter
- Professional layout inconsistent with the assignment type

### 2e. Track Changes & Comments

Check for:
- `<w:ins>` (insertions) and `<w:del>` (deletions) — tracked changes
- `comments.xml` — reviewer comments

**Red flags:**
- Complete absence of any revision history in a collaborative document
- Zero comments on a draft that was supposedly reviewed

## Phase 3: Reference Integrity Analysis

### 3a. Duplicate Detection

Extract all reference entries from the text (typically numbered [1], [2], etc. near the end). Compare by:
- Author lists (fuzzy match first 3 authors)
- Title similarity (first 60 characters)
- DOI (exact match)

**Red flags:**
- Same paper appearing under multiple reference numbers — a hallmark of LLM generation where the model doesn't maintain a persistent reference list

**Evidence strength if positive: STRONG**

### 3b. Reference Format Consistency

Check whether references are:
- Word field codes (citation manager) → genuine
- Plain text with consistent formatting → possibly manual but real
- Plain text with inconsistent formatting → suspicious
- Mix of DOI links as plain text vs. hyperlinks → suggests programmatic insertion

### 3c. Cross-Reference Validation (optional, if time permits)

For a sample of 3-5 references, verify via web search:
- Does the paper exist?
- Are the authors, year, journal correct?
- Does the DOI resolve?

LLMs sometimes fabricate plausible-looking references that don't exist.

## Phase 4: Content Analysis

### 4a. Font Diversity

Extract all fonts used in text runs:
```python
fonts_used = set()
for rFonts in root.findall('.//w:rFonts', ns):
    for attr in rFonts.attrib.values():
        fonts_used.add(attr)
```

**Red flags:**
- Only 1-2 fonts in a long document — consistent with programmatic generation with a single style
- No font variation for headings vs. body vs. captions

### 4b. Image Metadata

For each image in `word/media/`:
- Check JPEG EXIF data for software markers (matplotlib, Origin, PIL, Photoshop, etc.)
- Check PNG tEXt chunks for Software field
- Check TIFF tags

**Red flags:**
- All EXIF stripped (JFIF-only JPEGs) — consistent with images processed through a pipeline
- Presence of `PIL` or `Python` markers — images generated or processed by Python scripts

### 4c. Hyperlink Analysis

Count hyperlinks in `word/_rels/document.xml.rels`:
- How many are actual clickable links vs. plain text URLs in the body?
- A document with 29 DOI URLs in references but only 1 actual hyperlink → programmatic text insertion

### 4d. Filename vs. Content Discrepancy

Compare the .docx filename with the internal `dc:title`:
- Spelling errors in filename but correct in title → manual filename, generated content
- Completely different title → file was renamed

## Phase 5: Author Identity Investigation (if unknown author found)

If `dc:creator` or `cp:lastModifiedBy` contains an unrecognized name:

1. **Web search** the exact name
2. **Search with variations** (first name spelling variants + surname)
3. **Check LinkedIn** — look for university/location matches
4. **Check freelancing platforms** (Fiverr, Upwork) — look for academic writing services
5. **Check surname origin** — may indicate geographic/cultural context

**Record:**
- Full name match or closest match
- Location (especially if same city/university as the student)
- Professional background (technical capability to run LLM pipelines?)
- Any connection to academic writing services

## Phase 6: Report Generation

### Compile Evidence Table

For each indicator checked, assign a strength rating:

| Rating | Meaning |
|--------|---------|
| **Definitive** | Near-certain proof of programmatic/AI generation |
| **Very strong** | Highly indicative, very difficult to explain otherwise |
| **Strong** | Significant indicator, supports the case |
| Suggestive | Consistent with AI generation but has innocent explanations |
| Neutral | No evidence either way |
| Counter-evidence | Suggests genuine human authoring |

### Assess Origin Hypotheses

Always evaluate at least these three:

**Hypothesis A: Genuine human authoring**
The student wrote the document themselves in Word, possibly with minor AI assistance for grammar/phrasing.

**Hypothesis B: Student used AI personally**
The student prompted an LLM to generate the report, then assembled the output into .docx format themselves.

**Hypothesis C: Third-party involvement (contract cheating)**
The student outsourced the work to another person or service who used AI to generate the document.

Rate each hypothesis against the evidence. Highlight which is most likely.

### Recommended Handling

If evidence supports AI generation / contract cheating, include:
1. Lead with technical evidence in any confrontation — don't reveal identity findings first
2. Ask the student to explain their writing process before presenting evidence
3. Reserve metadata identity findings as corroborating evidence if the student denies
4. Note that findings should go through the university's academic integrity procedures

### Output Format

Write the report as a markdown file with this structure:

- Title: `# Forensic Analysis — [Document Title or Description]`
- Executive Summary (2-3 sentences)
- Evidence Summary Table
- Detailed Evidence (one subsection per indicator)
- Author Identity Investigation (if applicable)
- Assessment of Origin Hypotheses
- Recommended Handling
- Appendix: Raw Metadata

## Important Notes

- **This is a technical forensic tool, not an accusation engine.** The report presents evidence and assessments, not verdicts. Academic integrity decisions are made by humans through proper university procedures.
- **False positives are possible.** Some legitimate workflows (e.g., LaTeX-to-docx conversion, Google Docs export) can produce similar metadata patterns. Always consider alternative explanations.
- **The absence of indicators does not prove genuine authoring.** A sophisticated user could clean metadata, use Word-native formatting, and manually curate references. This tool catches careless or semi-automated AI use, not expert-level deception.
- **Handle identity findings with care.** Naming a specific person as a potential ghost-writer has serious implications. Present these findings only to authorized personnel through proper channels.
